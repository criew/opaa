    Betrieb¶

    Dieses Kapitel beschreibt die Bausteine einer OPAA-Installation und führt zu den Kapiteln, die für jeden Betriebsweg gleich gelten. Die Einrichtung beschreiben Docker Compose und Kubernetes, jede Umgebungsvariable die Konfiguration.

    Bausteine¶

    flowchart LR
    B[Browser] -->|HTTPS| RP[Reverse-Proxy<br/>oder Ingress]
    K[Externe<br/>KI-Werkzeuge] -->|/mcp, /api| RP
    RP --> F[Frontend<br/>nginx]
    F -->|/api/, /mcp| BE[Backend]
    BE --> DB[(PostgreSQL<br/>mit pgvector)]
    BE --> O[(Original-<br/>ablage)]
    BE --> SMTP[Mailserver]
    BE -.->|Ausgangs-<br/>proxy| M[Modell-<br/>dienste]
    BE -.-> I[Identitäts-<br/>anbieter]
    BE -.-> Q[Quellen]
    B -.->|Anmeldung| I
    P[Monitoring] -->|Metriken| BE

    Gestrichelt sind die Verbindungen, die über den Ausgangsproxy gehen können, und die Anmeldung des Browsers beim Identitätsanbieter.

    Baustein Aufgabe Pflicht Kapitel
    Reverse-Proxy oder Ingress TLS, Weiterleitung an das Frontend ja, sobald erreichbar Netzwerkzugang
    Frontend liefert die Oberfläche aus, reicht /api/ und /mcp an das Backend; ohne Zustand ja Frontend-Laufzeitimage
    Backend Suche, Antwort, Indexierung, Rechte, Verwaltung ja, eine oder mehrere Instanzen Backend-Laufzeitimage
    PostgreSQL mit pgvector einziger Zustand: Dokumente, Vektoren, Volltext, Rechte, Chats, Protokolle ja Datenbank
    Originalablage Originale der Uploads, im Dateisystem (auch Netzlaufwerk) oder in einem S3-Objektspeicher wie MinIO ja, sobald hochgeladen wird Originalablage
    Modelldienste je Rolle ein OpenAI-kompatibler Endpunkt: Chat und Embedding (Pflicht), Reranking und Spracherkennung (optional) Chat und Embedding Modelle
    Identitätsanbieter Anmeldung über OpenID Connect, etwa Keycloak; ohne ihn nur lokale Konten nein Authentifizierung
    Mailserver SMTP für Einladungen, Rücksetzlinks, Benachrichtigungen nein E-Mail-Versand
    Quellen angebunden über Konnektoren, etwa SMB-Freigaben, Nextcloud, Google Drive, SharePoint, Confluence, Feeds … nein Konnektoren
    Ausgangsproxy der eine Weg des Backends ins Netz, wenn das Haus einen verlangt nein Ausgangsproxy
    Externe KI-Werkzeuge greifen über MCP oder API mit persönlichen Zugangstokens zu nein, eigener Schalter Externe KI-Werkzeuge
    Monitoring Prometheus liest Metriken, ein Log-Sammler die Standardausgabe nein Logs und Metriken
    Sicherheitsmonitoring (SIEM) empfängt das Revisionsprotokoll ohne Pseudonyme als Syslog nein, eigener Schalter Ausleitung

    Gesichert wird nur, was Zustand hält: Datenbank, Originalablage und Geheimnisse (Sicherung und Wiederherstellung). Jede Verbindung, die OPAA selbst aufbaut, listet mit ihren Daten das Faktenblatt datenfluesse; was davon geprüft wird, steht unter Was bei jeder Änderung geprüft wird.

    Eine oder mehrere Backend-Instanzen¶

    Vorgabe ist eine Backend-Instanz; mehrere gleichrangige Instanzen gegen dieselbe Datenbank überstehen den Ausfall einer Instanz und lassen sich nacheinander aktualisieren (Mehrere Backend-Instanzen).

    Zeitzone¶

    • Gesetzt über TZ (Compose) bzw. backend.timeZone (Helm); Vorgabe UTC.
    • Bestimmt die Uhrzeiten geplanter Läufe (Löschläufe, Zeitpläne der Wissensbibliotheken, Feststellung der Nachfolge), Tages-, Monats- und Jahresgrenzen von Fristen, Erinnerungen und Datumsangaben in Mails.
    • Mit mehreren Instanzen auf allen gleich (Konfigurationsabdruck).

    Eine Organisation¶

    • Eine Installation hat genau eine Organisation; einen Weg, eine zweite anzulegen, gibt es nicht. Alle Konten, auch die aus Identitätsanbietern, gehören zu ihr.
    • Datenmodell und Prüfungen sind für mehrere Mandanten vorbereitet: Objekte tragen ihre Organisation, die Datenbank verbietet Verweise zwischen Organisationen, und ein Objekt einer fremden Organisation ist für jeden Aufruf „nicht gefunden“.
    • Mandantenbetrieb in einer Installation ist damit nicht gebaut; getrennte Mandanten bekommen getrennte Installationen.

    Drei Grundsätze¶

    • Die Datenbank ist die einzige Wahrheit. Dokumente, Vektoren, Volltext, Metadaten, Protokolle und Chats liegen in PostgreSQL; daneben nur die Originalablage der Uploads. Eine Sicherung umfasst beides.
    • Instanzen stimmen sich über die Datenbank ab. Eine Instanz genügt; mehrere teilen sich die Arbeit ohne weitere Infrastruktur (Mehrere Backend-Instanzen).
    • Rechte wirken in der Suche. Jede Suchabfrage trägt den Filter auf die lesbaren Bibliotheken; einen Administrator-Durchgriff gibt es nicht.
