Vor dem Update von `v0.1.0-rc.4`, für Kubernetes und Docker Compose gleichermaßen:

1. **Datenbank neu aufsetzen.** Dieser Stand migriert das Schema mit Flyway statt mit Liquibase und
   beginnt mit einer neuen Baseline je Modul; eine Datenbank von `v0.1.0-rc.4` startet nicht und lässt
   sich nicht übernehmen. Konten, Bibliotheken, Chats, Protokolle und Rechtehistorie gehen dabei
   verloren; Originale und Korpus bleiben (Handbuch, Kapitel Docker Compose, Abschnitt „Neu aufsetzen
   statt aktualisieren“; unter Kubernetes die Datenbank des Releases leeren).
2. **`SPRING_LIQUIBASE_ENABLED` umbenennen.** Wer die Variable in einer eigenen Compose- oder
   Werte-Datei setzt, setzt künftig `SPRING_FLYWAY_ENABLED`. Helm-Chart und
   `docker-compose.multi.yml` setzen sie selbst.

Keine neue Pflicht-Variable und kein neuer Pflichtwert im Chart; die Ausleitung an ein
Sicherheitsmonitoring bleibt ab Werk aus.
