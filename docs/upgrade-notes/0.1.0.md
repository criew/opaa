`v0.1.0` ist das erste stabile Release. **Wer einen Release-Kandidaten (`v0.1.0-rc.N`) betreibt,
setzt neu auf;** eine Datenmigration von den Release-Kandidaten gibt es nicht. Eine Datenbank eines
Kandidaten startet nicht („Migration checksum mismatch“).

Neuindizierung: ja, Dauer wie bei der Erstindizierung der Bibliotheken (nur für Betreiber eines Release-Kandidaten)

1. **Was verloren geht:** der gesamte Inhalt der Datenbank, also Konten, Gruppen, Bibliotheken,
   Chats, Nachweisprotokoll und Rechtehistorie, auch vor Ablauf ihrer Aufbewahrungsfristen. Wer
   Nachweise führt, zieht vorher einen Dump (`pg_dump`) und sichert die Originale.
2. **Konfiguration neu aufbauen:** `.env.docker` bzw. Werte-Datei nach dem Handbuch dieses Release
   neu aufbauen oder gegen das Kapitel Konfiguration, Abschnitt „Entfallene und veraltete
   Variablen“, prüfen. Seit den Release-Kandidaten sind Variablen umbenannt oder entfallen.
3. **Neu aufsetzen:**
   - **Docker Compose:** Ablauf im Handbuch, Kapitel Docker Compose, Abschnitt „Neu aufsetzen statt
     aktualisieren“.
   - **Kubernetes:** Backend auf null Pods skalieren, die Datenbank des Releases löschen und leer neu
     anlegen (Eigentümer, Erweiterung `vector` und gegebenenfalls ein eigenes Schema aus
     `OPAA_DB_SCHEMA`, wie im Kapitel Kubernetes, Abschnitt „2. Datenbank vorbereiten“; bei
     `evaluationDatabase.enabled` ihr Volume verwerfen), die Originale im Bucket bzw. Volume
     entfernen, dann `helm upgrade` auf `0.1.0`. Der erste Start steht im Installationsmodus.
