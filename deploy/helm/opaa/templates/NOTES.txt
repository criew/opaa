{{- if include "opaa.backend.rolling" . }}

{{ int .Values.backend.replicas }} BACKEND-POD{{ if gt (int .Values.backend.replicas) 1 }}S{{ end }}, AKTUALISIERUNG POD FÜR POD
  Ein Upgrade ersetzt die Pods einzeln (RollingUpdate), der nächste erst, wenn der neue bereit ist.
  Vorher erweitert der Migrations-Job das Schema so, dass die Vorgängerversion weiterläuft.
  helm rollback auf die Vorgängerversion ist deshalb ein Rückweg; über ein Release, das sich als
  Versionsgrenze ohne Rolling Update ausweist, nur die Datenbanksicherung. Einen Wert des
  Konfigurationsabdrucks ändert nur backend.updateStrategy: Recreate. Budgets wie Rate-Limits und
  Pools gelten je Pod; backend.installationBudgets teilt das Budget der Installation auf die Pods.
{{- else if gt (int .Values.backend.replicas) 1 }}

{{ int .Values.backend.replicas }} BACKEND-PODS, STRATEGIE RECREATE
  Ein Upgrade beendet alle Pods, bevor die neuen starten, und unterbricht den Betrieb kurz. So
  ändert sich ein Wert des Konfigurationsabdrucks. Budgets wie Rate-Limits und Pools gelten je Pod;
  backend.installationBudgets teilt das Budget der Installation auf die Pods.
{{- else }}

GENAU EINE BACKEND-INSTANZ
  Das Backend läuft als ein Pod mit Strategie Recreate. Ein Upgrade unterbricht den Betrieb kurz.
  helm rollback ist über eine Schemaänderung hinweg kein Rückweg - zurück geht es nur über die
  Datenbanksicherung.
{{- end }}
